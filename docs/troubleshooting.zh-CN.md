# 排障

现象、常见原因与解决办法。设置步骤见 [setup.zh-CN.md](setup.zh-CN.md)。[English](troubleshooting.md)

## 设置与访问

| 现象 | 常见原因 | 怎么办 |
| --- | --- | --- |
| 问自己的记录，Claude 凭常识作答、没有注明文件 | 会话不是开在知识库仓库上，或 CLAUDE.md 里没有注册表那一块 | 在知识库仓库上开会话。确认 CLAUDE.md 里有初始化写入的那一块，再问「我有哪些知识库？」 |
| skill 没出现 | 没有 `.claude/skills/`、解压多了一层目录，或没有推送 | 每个 skill 的 SKILL.md 必须在默认分支的 `.claude/skills/<skill>/SKILL.md`。改好后提交、推送，再开新会话 |
| 两个 skill 抢同一个请求 | 同一个 skill 装了两种语言版 | `.claude/skills/` 下每个 skill 只留一种 |
| 「这个库要在检出了仓库的编程助手会话中使用」 | 请求来自普通 claude.ai 对话，或会话检出的是别的仓库 | 在知识库仓库上用 Claude Code 开会话 |
| 「找不到 <owner>/<repo> 的检出目录」 | 当前目录的 origin 远程不是注册表里写的仓库 | 在库自己的检出目录里开会话；核对 `git remote get-url origin` 和 CLAUDE.md 里的 `backend.root` |
| 初始化不肯把仓库当新库 | 仓库根目录有 README.md、CLAUDE.md、AGENTS.md 以外的 Markdown 文件 | 新库用空仓库。已经有库的仓库需要手工补全 |
| 初始化拒绝写 CLAUDE.md | CLAUDE.md 已登记了别的库 | 一个仓库只放一个库；另一个库放到它自己的仓库 |

## Git

| 现象 | 常见原因 | 怎么办 |
| --- | --- | --- |
| 还没读文件就停下：`git pull --ff-only` 失败 | 检出目录有本地改动，或分支已经分叉 | 提交或去掉本地改动，或让分支与远程重新一致，再重复请求。skill 从不 reset 或 stash |
| 「提交在本地，推送失败」 | 没有推送权限、网络问题，或默认分支有保护规则 | 排除原因后自己运行 `git push`；推送成功才算交付完成。skill 推送到默认分支，分支保护必须允许 |
| rebase 冲突，交付停下 | 仓库在别处（另一个会话、github.com 上的编辑）改了同一个文件 | skill 已中止 rebase 并列出冲突文件。手工解决（通常是先 pull 再重复请求），绝不强推 |
| 云端会话推送不了 | claude.ai 的 GitHub 访问权限不包括这个仓库 | 给 Claude GitHub 应用开通这个仓库的权限，再开新会话 |

## 入库与回答

| 现象 | 常见原因 | 怎么办 |
| --- | --- | --- |
| 文件入库了，状态卡却没变 | 快速入库先入库，整合时才更新状态卡 | 说「整合」并审阅提出的改动。依赖未整合文件的回答会注明这一点 |
| 入库停在预览 | 每次写入前都先预览 | 回复「确认」写入，或说出要改的地方 |
| 大批入库很慢或中途停下 | 文件多，运行时间长 | 材料分批入库；在同一个对话里说「继续入库」。新对话会重新开始入库，已入库的文件自动跳过 |
| 回答说库里没有记录，可你明明入库了 | 用词不同，或文件还没入库 | 用文档里的说法再问，或问「<文档> 入库了吗？」查文件索引 |
| 「归档旧版」被拒绝 | GitHub 库没有归档文件夹 | 不用处理：旧版本都在 git 历史里 |

仍然解决不了：开一个 [issue](../../../issues)，附上你说的话、得到的回复，以及去掉私人名称后的 `_kb.json`。
