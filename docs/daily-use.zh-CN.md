# 日常使用

每件事怎么说、之后会发生什么、哪些步骤要等你回复。每个库是一个独立仓库，在那个仓库的会话里操作。[English](daily-use.md)

## 怎么说

| 想做的事 | 说 | 会发生什么 | 要等你吗 |
| --- | --- | --- | --- |
| 提问 | 直接问 | kb-query 先读状态卡，再读需要的文件，每条事实注明依据文件 | 不用 |
| 问怎么变过来的 | 「以前是怎么写的？」「这个怎么变的？」 | 先看变更记录和状态卡；不够时查 git 历史，旧版本注明提交日期与短哈希 | 不用 |
| 记一句 | 「记一下：……」 | kb-note 存成随手记放进 Quick-Notes 文件夹，提交并推送，回复文件名 | 不用 |
| 留存回答 | 「把这个回答存下来」 | 问题、回答和依据文件一起存成随手记 | 不用 |
| 整理文档入库 | 指明、粘贴或附上材料，说「入库」 | 每份材料分区、命名、查重、判定版本后写入、提交并推送，写入后立刻可查 | 开始时有一次预览，回复「确认」 |
| 继续大批入库 | 「继续入库」「结束入库」 | 按开始时排好的计划处理下一批；只在同一个对话里有效 | 每批的预览 |
| 更新状态卡 | 「整合」 | 给上次整合以来入库的文件补关键结论，把状态卡改动编号列出，每个数值都对照出处核对 | 逐条由你决定采用与否 |
| 整理随手记 | 「整理随手记」 | 随手记按议题归并成材料入库，再把已入库的随手记移入已入库文件夹 | 先预览，移动前再回复「确认」 |
| 检查库 | 「体检」 | 报告过期、重复、缺漏和格式问题，并抽查状态卡数值 | 不用；不改任何文件 |

入库时加上「完整入库」，每个文件入库时就当场更新状态卡，不用等整合。

「归档旧版」不适用于 GitHub 库：新版本原地覆盖旧版，旧版由 git 历史保留。

## 一份文档的经历

```text
材料 --「入库」--> 已入库：命名、编入索引、立刻可查，一个提交
                    |
                    +--「整合」--> 写入关键结论，
                                   提出状态卡改动 --你同意--> 状态卡更新，一个提交
                    |
同一文档的新版本，同名 --> 覆盖原文件；旧版本留在 git 历史里
```

文件整合之前，状态卡可能还没反映它。依赖这类文件的回答会注明这一点；有文件等着整合时，skill 每个对话提醒一次。

## 材料从哪里来

材料在原处读取，不移动、不修改、不提交；提交的只是整理好的库文件。本地会话里，指明你电脑上的文件或文件夹；文件多时会分批计划。任何会话里都可以贴文字；Claude Code 应用支持时也可以附上文件。手机上最适合记随手记和提问；大批文档在电脑上入库。

## 好用的节奏

- 材料一来就入库，入库后立刻可查。
- 收到提醒时说「整合」，或每周一次。也可以让定时任务（Claude Code 的定时任务）每晚说「定时整合」：改动自动采用，依据核查报警的改动转为待决事项，有整合或出错时推送一条通知。
- kb-note 提示随手记攒多了时，说「整理随手记」。
- 每月做一次「体检」。

什么都不会丢：每个文件的每个旧版本都在 git 历史里，仓库的提交记录列出每一轮操作。
