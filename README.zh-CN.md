# repo-wiki（GitHub 仓库常青知识库）

由 Claude Code 维护、放在你自己私有 GitHub 仓库里的个人知识库，内容始终是现行的。在终端、桌面应用或手机上的 claude.ai/code 里提问，得到的是一个现行答案，并注明出自哪个文件；每次改动都是一个提交，git 保留以前的每一版。三个 skill 完成工作；知识库就是你自己仓库里的一个普通 Markdown 文件夹。

[English](README.md)

## 用起来是什么样

向虚构的[示例库](examples/)提问（回复有删节）：

```text
你：    我的胆固醇趋势如何？
Claude：知识库：生活库
        2025 年体检总胆固醇 5.6 mmol/L，高于参考值 5.2；建议 12 个月后复查。
        库里目前只有这一次体检，还谈不上趋势。
        依据：02_Checkups_report_2025-annual.md
```

答案来自库的状态卡，每行一条现行事实，各自注明出处：

```text
1. 2025 年体检：总胆固醇 5.6 mmol/L，高于参考值 5.2；建议 12 个月后复查
   （依据：02_Checkups_report_2025-annual）
2. 云存储订阅 2026-11-01 续费，每年 99.00（依据：……）
```

把 2026 年的体检报告入库后说「整合」：第 1 条会被提出更新，你同意后才改，这次改动记在提交里。问「以前是怎么写的？」，旧版本从 git 历史里取出，并注明是哪个提交。

## 你能得到什么

- **现行答案，而不是最相近的匹配**：文档的新版本沿用旧版的文件名、替换旧版，过时的方案和旧说法不会再被当作答案。
- **每条事实都有出处**：每个回答注明依据文件；库里没有记录的，就说没有记录，绝不凭记忆补上。
- **每个版本都留着**：每次入库、随手记或状态卡更新都是一个推送到你仓库的提交；旧版本留在 git 历史里，问「怎么变的」时引用对应提交。
- **你的仓库，你说了算**：知识库在你自己的私有仓库里，任何编辑器或 github.com 上都能读；每次写入前都先给你看。

| skill | 你说 | 它做什么 |
| --- | --- | --- |
| kb-note | 「记一下」「把这个回答存下来」 | 把一句话或一个回答存成随手记，日后再正式入库 |
| kb-ingest | 「入库」「整合」「体检」「开始使用知识库」 | 整理材料入库，每份文档只留一个现行版本，经你确认后更新状态卡，检查知识库 |
| kb-query | 库里可能有答案的任何问题 | 先查库，再作答，每条事实注明出自哪个文件 |

全部口令及之后会发生什么：[docs/daily-use.zh-CN.md](docs/daily-use.zh-CN.md)。

## 快速开始

你需要 Claude Code（终端、桌面应用，或网页与手机上的 claude.ai/code）、git、Python 3.8 及以上，以及一个 GitHub 账号。

1. 在 GitHub 上为知识库新建一个空的**私有**仓库。里面会放个人或工作材料，绝不能设为公开。
2. 从 [Releases](../../releases) 下载 `kb-note`、`kb-query`、`kb-ingest` 三个 zip（带 `-zh` 的是中文口令版），解压到知识库仓库的 `.claude/skills/` 下，提交并推送。
3. 在 Claude Code 里打开这个仓库，说「开始使用知识库」。Claude 会问两个问题、给出预览，写好知识库，把注册表写进仓库的 CLAUDE.md，并推送一个提交。
4. 检查：在这个仓库上开一个新会话，问「我有哪些知识库？」。Claude 说得出你的库，就设置好了。

详细步骤：[docs/setup.zh-CN.md](docs/setup.zh-CN.md)。遇到问题：[docs/troubleshooting.zh-CN.md](docs/troubleshooting.zh-CN.md)。

## 适不适合你

- **适合**一个人维护自己的知识（生活或工作），并且愿意用 Claude Code。随手记和提问在手机上的 claude.ai/code 里就能做；大批材料入库最好在本地会话里做，原始文件就在磁盘上。要先把大量文件转成 Markdown，可以用 [doc2kb](https://github.com/walkwithedi/doc2kb) 这类转换工具。
- **一库一仓**：生活库和工作库是两个仓库，各自开会话使用。
- **不适合**多人同时写同一个库（推送前会 rebase，遇到冲突就停下交给你处理），想在普通 claude.ai 对话里不经 Claude Code 使用的人，以及无法保证仓库私有的人。

## 怎样保持常青

- **名称即版本**：文档的新版本沿用旧版的文件名并覆盖它，旧版由 git 历史保留。
- **每个库一张状态卡**：存放每个常被问到的问题的现行答案。只有新材料与之矛盾时才改写，改动先经你确认；脚本会核对没有漏掉任何一行，数字和日期都能在出处里找到。
- **有证据才改**：每个判断（重复、新版本、事实变化）都要有原文引语；没有就取保守做法。
- **先入库，后整合**：每个文件一入库就能查到；更新状态卡在你说「整合」时进行。
- **一轮一个提交**：每次交付连同写入日志一起提交，推送到默认分支；推送成功才算写入完成。

背后的道理：[docs/methodology.zh-CN.md](docs/methodology.zh-CN.md)。

知识库仓库里的样子：

```text
my-life-kb/
  .claude/skills/          kb-note、kb-query、kb-ingest
  CLAUDE.md                注册表，以及告诉 Claude 这个库存在的那一行
  _kb.json, _kb-params.md  库的配置
  00_Spec.md               分区与议题、术语修正、阈值
  00_Status-Card.md        现行事实，各自链接到出处
  01_File-Index.md         每份已入库文档，带原文件名与哈希
  01_Open-Items.md         到期与待办（生活库）或待决事项（工作库）
  01_Change-Log.md         事实随时间的变化
  02_Checkups_report_2025-annual.md
  ...
  Entities/  Quick-Notes/
```

两个预设用来起步：生活（健康、财务、保险、住房、家庭、证件与法律、设备、订阅与出行、学习、参考）和工作（目标与计划、项目与事务、方案与交付物、会议与决策、制度流程、组织与职责、数据与报表、参考与模板）。所有文件名都可以配置。
